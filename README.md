# ซากุระ — ระบบสั่งอาหารร้านอาหารญี่ปุ่น (ผ่านแท็บเล็ตบนโต๊ะ)

ระบบสั่งอาหารแบบเรียลไทม์ แยกตามบทบาท: ลูกค้า (แท็บเล็ตบนโต๊ะ) · ครัว · พนักงานบริการ · แคชเชียร์

## วิธีรัน
1. เปิด Terminal ในโฟลเดอร์นี้
2. `npm install`
3. `npm start`
4. เปิด `http://localhost:3000`

## ใช้งานหลายเครื่องในร้าน (LAN / ออนไลน์ในร้าน)
รันเซิร์ฟเวอร์ที่ **เครื่องเดียว** (เช่นเครื่องแคชเชียร์) แล้วให้เครื่องอื่น (แท็บเล็ตลูกค้า, จอครัว, จอบริการ) เปิดผ่าน IP ของเครื่องนั้นในวง Wi‑Fi เดียวกัน:
- ดู IP เครื่องเซิร์ฟเวอร์ (Windows: `ipconfig` → IPv4 เช่น `192.168.1.50`)
- เครื่องอื่นเปิด `http://192.168.1.50:3000`
- ทุกจอ**ซิงก์กันทันที (real-time)** ผ่าน Server‑Sent Events เช่น ครัวกด “เสร็จสิ้น” → ออเดอร์เด้งไปจอบริการให้เสิร์ฟทันที โดยไม่ต้องรีเฟรช
- หมายเหตุ: ต้องเปิดเครื่องเซิร์ฟเวอร์ไว้ตลอดเวลาทำการ (ถ้าเครื่องนี้ปิด/หลับ จออื่นจะใช้ไม่ได้)
- ถ้าเปิดไม่ได้จากเครื่องอื่น ให้อนุญาต Node.js ผ่าน Firewall ของเครื่องเซิร์ฟเวอร์

## หน้าแรก: เลือกบทบาท
- เปิดหน้าแรกจะให้เลือก **ลูกค้า** หรือ **พนักงาน**
- **แท็บเล็ตลูกค้าแต่ละโต๊ะ**: ตั้งค่า (bookmark) ให้เปิดที่ `http://<server>:3000/?table=<เลขโต๊ะ>` ครั้งเดียว เช่นโต๊ะ 5 → `/?table=5` ระบบจะจำโต๊ะไว้ กด “ลูกค้า” แล้วเริ่มสั่งได้เลย (ลูกค้าไม่ต้องเลือกโต๊ะเอง)
- **พนักงาน**: กด “พนักงาน” → กรอก **PIN** → เลือกแผนก ครัว/บริการ/แคชเชียร์

### PIN พนักงาน
ตั้งค่าได้ที่ต้นไฟล์ `index.js`:
```js
const STAFF_PIN = "1234";   // เปลี่ยนรหัสได้ / ใส่ "" เพื่อปิดการใช้ PIN
```

## การตั้งค่าร้าน / พร้อมเพย์
ที่ต้นไฟล์ `index.js`:
```js
const RESTAURANT = {
  name: "ซากุระ", nameEn: "SAKURA", tagline: "ร้านอาหารญี่ปุ่น",
  promptpay: "0812345678"   // << ใส่เบอร์พร้อมเพย์จริงของร้าน (มือถือ 10 หลัก หรือเลข 13 หลัก)
};
```
QR หน้าชำระเงินสร้างตามยอดบิลจริง (มาตรฐาน EMVCo PromptPay) สแกนจ่ายได้จริง และ **ไม่พึ่งอินเทอร์เน็ต** (ใช้ไลบรารีสร้าง QR ที่ฝังในโปรเจกต์ `public/qrcode.min.js`)

## Flow การทำงาน
1. ลูกค้าเลือกเมนู → ปรับ add‑on (เห็นราคารวมเรียลไทม์) → `เพิ่มลงตะกร้า` → กลับหน้าเมนูพร้อมแจ้งเตือน + แถบตะกร้าลอย
2. `ยืนยันการสั่งอาหาร` → ออเดอร์เข้าครัว, โต๊ะเป็น `ไม่ว่าง`
3. ครัวเห็นออเดอร์ (พร้อมเวลา/เวลาที่ผ่านไป, เตือนสีเมื่อรอนาน) → `เสร็จสิ้น → ส่งเสิร์ฟ`
4. จอบริการขึ้นออเดอร์ทันที (real‑time) → `เสิร์ฟแล้ว`
5. แคชเชียร์ดูบิล (แยกตามออเดอร์+เวลา) → **ปิดบิลได้ต่อเมื่อเสิร์ฟครบทุกรายการ** → `รับชำระเงิน`
6. เลือกเงินสด (คำนวณเงินทอน + ปุ่มด่วน) หรือ QR พร้อมเพย์ → ยืนยัน → ปิดบิล, โต๊ะกลับเป็น `ว่าง`
7. เมื่อปิดบิลแล้ว **ประวัติการสั่งของโต๊ะนั้นจะหายจากหน้าลูกค้า** (ลูกค้าใหม่ไม่เห็นของเก่า) แต่ข้อมูลยังเก็บใน `payments`/`orders` เพื่อทำรายงานย้อนหลังได้

## รายการปรับปรุงรอบนี้
- หน้าแรกเลือกบทบาท (ลูกค้า/พนักงาน) + PIN กันลูกค้าเข้าหน้าพนักงาน
- เรียลไทม์ข้ามเครื่องด้วย SSE (ครัว↔บริการ↔แคชเชียร์↔ลูกค้า) แทนการรีเฟรชทุก 8 วิ
- ปิดบิลไม่ได้ถ้ายังเสิร์ฟไม่ครบ
- ซ่อนประวัติที่จ่ายแล้วจากหน้าลูกค้า (คงข้อมูลใน DB)
- ตัด add‑on: ซูชิเหลือเฉพาะ “เพิ่มวาซาบิ/โชยุ/ขิงดอง” (วาซาบิ/โชยุเสิร์ฟให้ทุกโต๊ะอยู่แล้ว) · เครื่องดื่มไม่มี add‑on
- Responsive รองรับมือถือและแท็บเล็ต
- รูปอาหารเปลี่ยนชื่อไฟล์เป็นอังกฤษ (กันชื่อไทยเพี้ยนตอน zip/ย้ายเครื่อง)
- ไฟล์ **`ERD.drawio`** — แผนผังฐานข้อมูล เปิดที่ https://app.diagrams.net หรือส่วนขยาย Draw.io ใน VS Code

## ฐานข้อมูล (food.db / SQLite)
7 ตาราง: `category`, `menu`, `addon`, `orders`, `order_items`, `payments`, `tables_status`
ทุกความสัมพันธ์เป็นเชิงคีย์ (FOREIGN KEY) แบบ One-to-Many ทั้งหมด 6 เส้น:
- category 1:N menu, category 1:N addon (menu/addon อ้าง `category_id`)
- tables_status 1:N orders, tables_status 1:N payments
- orders 1:N order_items, menu 1:N order_items

เดิม menu กับ addon ผูกกันผ่านคอลัมน์ `category` (TEXT) ซึ่งไม่ใช่คีย์ — ปรับเป็น normalize โดยเพิ่มตาราง `category` แล้วให้ทั้งสองอ้างด้วย `category_id` (FK) จึงไม่มีความสัมพันธ์ Many-to-Many อีกต่อไป (รายละเอียดดู `ERD.drawio`)

ไฟล์ `food.db` จะถูกสร้าง/เติมข้อมูลอัตโนมัติเมื่อรันครั้งแรก (ถ้ามี `food.db` เวอร์ชันเก่าที่ใช้ `category` แบบ TEXT ระบบจะปรับโครงสร้างให้อัตโนมัติ)
